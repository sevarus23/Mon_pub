# Контрибьютинг

Спасибо за интерес к Mon_pub! Любой вклад приветствуется — от исправлений опечаток до новых фич.

## Быстрый старт

1. **Форкни репозиторий** (кнопка Fork в правом верхнем углу)
2. **Клонируй форк** и создай ветку от `main`:
   ```bash
   git clone https://github.com/<твой-логин>/Mon_pub.git
   cd Mon_pub
   git checkout -b feat/короткое-описание
   ```
3. **Настрой окружение** — инструкции в [README.md](README.md) (раздел «Локальный запуск»)
4. **Сделай изменения и запусти тесты** (см. ниже)
5. **Открой Pull Request** в ветку `main` основного репозитория

## Именование веток

| Префикс     | Для чего                           |
|-------------|------------------------------------|
| `feat/`     | новая функциональность             |
| `fix/`      | исправление бага                   |
| `chore/`    | рефакторинг, зависимости, CI       |
| `docs/`     | документация                       |
| `test/`     | только изменения тестов            |

Пример: `feat/global-search-filters`

## Коммиты

Пиши коммиты в повелительном наклонении на русском или английском:

```
Add filter by publication year
Fix duplicate articles in global search
```

Одно изменение — один коммит, если это возможно. Не смешивай рефакторинг и фичу.

## Тесты

**Backend:**
```bash
cd backend
pip install -r requirements.txt
pytest
```

**Frontend:**
```bash
cd frontend
npm install
npm test
```

CI автоматически прогонит обе наборы на каждый PR. PR не будет смёрджен, пока чеки **Backend Tests** и **Frontend Tests** не станут зелёными.

## Pull Request

- Название PR: кратко и по делу (`Add Scopus quartile filter`)
- В описании укажи **зачем** это изменение, а не только что делает
- Приложи скриншоты, если менял UI
- Свяжи с issue, если он есть: `Closes #42`
- Для крупных фич сначала открой issue с RFC — обсудим подход до написания кода

## Стиль кода

- **Python:** PEP 8, type hints обязательны для публичных функций
- **TypeScript:** строгий режим, никаких `any` без причины
- **Форматтеры:** `black` + `isort` для backend, `prettier` для frontend (конфиги в репо)

## Что делать НЕ надо

- Не коммить секреты, `.env`, ключи, токены
- Не меняй зависимости «заодно» в PR с фичей — выделяй в отдельный `chore/bump-deps`
- Не пересобирай `package-lock.json` без причины
- Не форсь-пушь в свою ветку после получения ревью (ломает контекст комментариев) — используй обычные коммиты
