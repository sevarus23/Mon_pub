## Правила обновления

### Белый список

Официальная [полная JSON-выгрузка](https://journalrank.rcsi.science/ru/record-sources/download/?dataType=Json)
загружается при ежедневном задании после парсинга статей. Ручное действие
`POST /api/articles/update-white-list` также обновляет справочник, а не только читает старый кэш.
Повторные успешные загрузки ограничены одним разом в час в рамках процесса.

Применяется последний непустой утверждённый `level_YYYY`; `date_discontinued`
снимает включение независимо от старого уровня. Активная запись приоритетнее исторической.
Конфликтующие активные записи должны разрешаться официальным адресным API до сохранения.
В выгрузке 17.09.2026 так разрешены ISSN `2709-8028` и `2709-8036`:
API вернул уровень 4; выбор сохранён в `resolved_conflicts` метаданных.
Повреждённая/усечённая выгрузка не заменяет предыдущий снимок. Падение количества
ISSN или включённых ISSN более чем на 10% требует ручной проверки.

При недоступности РЦНИ ручное действие возвращает ошибку; ежедневное задание
использует последний пригодный снимок. Метаданные отражают фактическую успешную загрузку,
а не факт открытия страницы. Ошибка записи метаданных журналируется отдельно.

Для обновления снимка репозитория скачайте официальный файл в `Temp` проекта,
затем из `backend` выполните:

```powershell
python scripts/import_white_list.py '<путь к официальному JSON>'
```

### Scopus

Скачайте текущий Source List по ссылке на официальной странице Elsevier.
Из `backend` выполните:

```powershell
python scripts/import_scopus_sources.py '<путь к официальному XLSX>' --compare data/scopus_issns.json --output data/scopus_issns.json
```

Уточните аргументы через `--help`. Зафиксируйте версию, URL, дату и SHA256 исходного
файла в `data/source_metadata.json`, затем проверьте diff и тесты.
Импортируются основной список и серийные конференции с профилем Scopus;
accepted-only и ISBN-only записи не включаются. Неактивные источники с историческим
покрытием сохраняются. Наличие ISSN не доказывает индексацию конкретной статьи.

### SJR и CORE

SJR 2025 хранится в `backend/data/scimagojr_2025.csv` без изменения исходных байтов.
Первичный источник — SCImago Journal & Country Rank. Официальная загрузка по-прежнему
возвращает HTTP 403, поэтому с разрешения пользователя использован публичный снимок
`barais/hal-irisa-scripts`, зафиксированный коммитом
`c815d75a9875b6fe8fc3aac853887c5ec03aed9c` от 30.04.2026.

- SHA256: `ead12360e11e9ebc2f4eb7280315540d0bfac69897f9f3b722ebe5039c43d523`.
- CSV содержит поле `Total Docs. (2025)`, 32 193 уникальных Sourceid и все нужные поля квартилей.
- У 30 412 журналов SJR, H-index, названия и цитирований/документ совпали с
  [независимой репликой](https://github.com/Michael-E-Rose/SCImagoJournalRankIndicators/tree/ed15f2e474c0331d09877422d5e6eefed932173f).
- Вторая реплика не содержит квартилей: полная независимая сверка именно квартилей не выполнена.
  Для Sourceid `130105` отличается состав ISSN; исходный снимок не исправлялся догадками.
- Атрибуция SCImago и ссылка на публичную копию сохранены в метаданных и интерфейсе.
  Основание использования: [официальный FAQ SCImago](https://www.scimagolab.com/faqs-2/).

Для следующего выпуска сначала получить официальный файл либо проверить происхождение
снимка, фактический год внутри CSV, структуру, полноту и контрольную сумму. Затем
добавить новый файл, изменить `SJR_FILENAME`/`SJR_YEAR` в `app/services/sjr.py` и метаданные.
Проверить тесты до запуска `update-quartiles`; несовпадение версии нельзя скрывать переименованием файла.
Повторное применение исправляет отличающиеся квартили, а не только пустые.
CSV 2024 сохранён как исходный снимок для осторожного снятия устаревших значений при переходе,
но не используется как запасная версия вместо 2025.

Штатное обновление проверяет SHA256 снимка и год до обращения к БД. Для имеющих
текущий ранг ISSN применяется значение 2025. Если ISSN теперь без квартиля (`-`)
или отсутствует, старое значение снимается только при точном совпадении с однозначным
значением снимка 2024. Неизвестные и отличающиеся значения сохраняются; конфликтующие
ISSN в старом снимке исключены из такой очистки. Происхождение квартиля в БД не хранится,
поэтому ручное значение, совпадающее со справочником 2024, отличить невозможно.
Запрос обновления дополнительно проверяет, что значение не изменилось после чтения.

После отдельного разрешённого деплоя запустить `POST /api/articles/update-quartiles`
на подтверждённом экземпляре либо проверить выполнение штатного задания, затем сверить
источники и метаданные. Замена CSV в репозитории сама по себе не обновляет production-БД.

CORE: сравнивать с официальным экспортом ICORE2026. Текущий код обрабатывает
обычные ранги A*/A/B/C; 25 записей с Australasian B/C в полном справочнике
не участвуют в существующем сопоставлении. Это ограничение модели данных, не устаревание файла.

## CI/CD и корпоративный домен

Подтверждено в GitHub `sevarus23/Mon_pub`:

- `tests.yml`: backend/frontend тесты для PR и `main`; оба статуса обязательны для merge.
- `publish-images.yml`: после push в `main` собирает и публикует backend/frontend в GHCR.
- `deploy.yml`: после тестов выполняет SSH-деплой в `/opt/mon_pub` через Docker Compose.
  Адрес находится в секрете `SERVER_HOST` и не установлен аудитом.
- `k8s/base/apps.yaml`: использует GHCR-образы, но не содержит ingress корпоративного домена.

Наличие этих workflow **не доказывает**, что они обновляют
`mon-pub.global.ai.innopolis.university`. В репозитории нет Azure pipeline или Azure remote.
На 17.09.2026 `https://code.university.innopolis.ru/AI/` недоступен по TCP из Edge
и командной строки. Это не свидетельствует об истечении credentials.
Нужно восстановить сетевой доступ и установить точные проект/pipeline/кластер.

После подтверждённого корпоративного деплоя проверить версию образа, доступность
`/mon_pub/api/articles/reference-data`, даты в интерфейсе и повторно сверить уровни
с `/mon_pub/api/articles/sources-table`. Перед ручным запуском обновлений проверить,
что маршрут ведёт именно в нужный экземпляр. Не считать публикацию образа деплоем.

Backend Dockerfile копирует целиком `app/` и `data/`: новый модуль метаданных
и справочники, включая SJR 2025, входят в контекст будущей сборки. Образы этого PR ещё не опубликованы.
Скрипты `scripts/` служат для подготовки репозитория
и не нужны контейнеру во время работы.
